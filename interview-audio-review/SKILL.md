# 面试录音复盘

按用户意图生成可追溯的纯转写稿或面试复盘报告。两种模式都以带时间戳的真实语音证据为基础。

## 输入材料

可以接收一个或多个音频、视频、已有转写稿，或这些材料的组合。同时使用用户提供的岗位说明、简历、项目资料、公司背景、角色信息和专业词汇表。

默认在本地处理录音。未经用户明确授权，不得上传录音或调用外部转写服务。

收到音频或视频后，先运行真实预检，检查时长、格式、声道、操作系统、芯片或 GPU、内存、磁盘、本地模型和当前环境可用的转写工具。选择或配置转写方案前，阅读 [转写方案选择](references/transcription-routing.md)。首次配置本地环境时，阅读 [本地安装与运行](references/local-setup.md)。

## 输出模式

先按用户原话选择模式，不要把纯转写请求扩展成复盘：

- **Transcript 模式：** 用户说“转写、文字稿、字幕、逐字稿”且没有要求分析时，最终只输出 `<原文件名>.transcript.md`。读取 [转写稿格式](references/transcript-format.md)。
- **Review 模式：** 用户要求“复盘、分析、评价、改进建议、推荐回答或问答还原”时，最终只输出 `<原文件名>.review.md`。读取 [报告格式](references/report-format.md)。
- 同时要求转写和复盘时使用 Review 模式，因为报告已经保留纠错后的真实问题与回答；只有用户明确要求两个独立文件时才同时输出。

## 默认运行策略

- Apple 芯片 Mac 默认使用 `mlx-whisper`。脚本从 Skill 目录逐级向上查找 `models/whisper-large-v3-turbo`；本地模型不存在时才使用 `mlx-community/whisper-large-v3-turbo` 仓库标识。
- Windows 和 Intel Mac 默认使用 `scripts/transcribe_faster_whisper.py`。普通 CPU 使用 `small` + INT8；可用 NVIDIA GPU 使用 `turbo` + FP16。`faster-whisper` 默认启用 VAD，模型首次运行时下载到本地缓存。
- Apple 芯片上超过十五分钟的录音默认运行 `scripts/transcribe_chunked.py`：先用 FFmpeg VAD 建立静音和语音时间轴，再做十分钟父分片、十秒重叠并合并绝对时间轴。Windows 和 Intel Mac 继续使用自带 Silero VAD 的跨平台脚本。
- 脚本发现连续重复、长时间短句、常见字幕幻觉、异常文字系统或内部循环文本时，只重试精确异常窗口一次。重试后仍异常就保留原始证据并标记精确不可靠范围，不得重转整个父分片或无限重试。
- 清晰的双人面试默认采用“带时间戳转写 + 对话语义推断角色”的快速路线；只有角色混淆、插话或多人对话明显影响问答还原时，才启用本地说话人分离。
- 首次运行先执行 `scripts/preflight.py`，再用 `transcribe_chunked.py --preflight-sample` 自动选择五分钟语音密集片段，检查术语识别、角色区分、转写稳定性和本机运行情况。处理速度明显不适合当前任务时，先关闭非必要的逐词时间戳和完整说话人分离，再根据设备资源改用较小的本地模型；技术术语错误明显时不要降低模型。

## 工作流程

1. 创建隔离的临时运行目录
   - 不修改原始录音。
   - Apple 芯片长录音由 `scripts/transcribe_chunked.py` 创建系统临时目录；Windows 和 Intel Mac 调用 `scripts/transcribe_faster_whisper.py` 时省略 `--output`，由脚本创建同样带清理标记的临时目录。
   - 音频分片、原始转写、合并转写、纠错草稿和分析草稿全部放入该目录。不得把中间 JSON、分片音频或纠错稿写到原录音目录。
   - 在最终产物完成前，临时转写是事实证据层；记录源文件名、处理方式、处理时间和分段时间戳。
   - 长录音脚本启动后立即输出 `RUN_DIR`，每个父分片完成后保存检查点。可恢复的中断使用相同参数和 `--resume <RUN_DIR>` 继续；只有确认无法恢复时才按失败流程清理。

2. 转写并区分说话人
   - Apple 芯片长录音运行 `scripts/transcribe_chunked.py`，十五分钟及以下可运行 `scripts/transcribe_local.py`；Windows 和 Intel Mac 运行 `scripts/transcribe_faster_whisper.py`。所有输出都必须位于本次临时目录。
   - 先根据问题句式、回答长度、上下文和轮次推断面试官与候选人；不要为了说话人标签默认运行较重的分离模型。
   - 只有快速路线不能可靠还原问答时，才使用本地 `pyannote.audio` 的开源模型进行说话人分离。
   - 使用姓名、缩写、技术名词、公司名、中英混说词汇和行业词汇作为识别提示。
   - Apple 芯片默认启用 FFmpeg VAD，跳过长静音但保留绝对时间轴；重叠区按片段中点选择并做文本相似度去重。跨平台脚本的直接转写必须启用 VAD，并检查长静音附近的异常文本。
   - 可疑片段只重试一次。两次结果都不可靠时在最终产物中标记时间范围和原因，不根据上下文补写。
   - 听不清时不得补写。使用 `[听不清]`、`[多人重叠]` 或 `可能是：Kubernetes` 等明确标记。

3. 在临时目录建立两层转写
   - **原始识别稿：** 尽可能贴近语音识别模型的原始输出，包含时间戳和可用时的说话人标签，作为不可改写的证据层。
   - **纠错转写稿：** 只修正高置信度的识别错误、标点、断句和专业术语。会影响含义的停顿、重复和自我修正应当保留。
   - 每个实质性修改都记录为：`时间戳 | 原始文本 | 纠正文本 | 原因 | 置信度`。
   - 不得在纠错转写稿里把不完整、较弱或事实错误的回答改成更好的答案。

4. 生成纠错转写稿
   - Transcript 模式按 [转写稿格式](references/transcript-format.md) 输出带时间戳正文。可以先运行 `scripts/render_transcript.py` 生成草稿，再完成角色映射和高置信度纠错。
   - 听不清、多人重叠或两次都异常的范围保留明确标记；不得为追求可读性补写。
   - Transcript 模式完成本步骤后直接进入验证和清理，不生成改进建议或推荐回答。

5. 一一还原面试问答（仅 Review 模式）
   - 只有对话证据充分时，才把说话人映射为 `面试官` 和 `候选人`；否则保留 `说话人 A/B` 并说明不确定性。
   - 按时间顺序恢复问题和回答。重要追问用 `Q3.1`、`Q3.2` 编号，不要合并后遗漏追问含义。
   - 每个问题和回答都附开始、结束时间戳。
   - 问候、流程沟通和题外讨论可单独概括，不混入正式问答。
   - 报告先展示经过高置信度纠错的真实回答，再给出改进建议和推荐回答。不得用推荐回答覆盖候选人的原话。

6. 复盘每道回答（仅 Review 模式）
   - 复盘必须基于真实问题、岗位背景，以及录音或用户材料中出现的信息。
   - 从切题程度、表达结构、正确性与深度、事实依据和沟通表现中提炼最有用的改进建议。
   - 指出遗漏点、风险表述、缺少依据的主张，以及面试官可能产生的顾虑。逐题部分只使用报告模板规定的小节，不添加额外分析模块。
   - 如果外部技术事实核查会显著影响复盘，只有在已经获得授权时才执行；否则先询问用户。外部资料必须单独引用，不得混入录音证据。

7. 生成推荐答案（仅 Review 模式）
   - 推荐答案必须忠于候选人的真实经历，不得虚构公司、项目、数字、工具、职责范围或成果。
   - 缺少事实时使用 `[补充真实指标]`、`[补充本人实际职责]` 等醒目占位符。
   - 生成自然、适合口头表达的详细答案，通常采用“先说结论—给出依据—说明权衡或反思”的结构。
   - 只有行为类问题适合时才使用 STAR，不要把所有问题强行套入 STAR。
   - 推荐回答必须分点呈现，信息完整，能够直接用于口头回答。
   - 只有确实存在需要用户如实补充的事实或值得准备的延伸信息时，才添加“补充（如有）”；没有内容时省略该小节。

8. 只输出当前模式的最终产物
   - Transcript 模式阅读 [转写稿格式](references/transcript-format.md)，最终只保存 `<原文件名>.transcript.md`。
   - Review 模式阅读 [报告格式](references/report-format.md)，最终只保存 `<原文件名>.review.md`。
   - 已存在同名产物时生成带时间戳或递增编号的新版本，不得覆盖旧文件。
   - 处理方式、模型、耗时、内部纠错记录和识别异常只用于执行与核对，不在最终产物中展开；只有它们直接影响内容可信度时，才简短说明证据限制。

9. 验证并清理本次中间产物
   - 先运行 `scripts/validate_output.py <最终文件> --mode transcript|review`，不得只按正文长度或关键词判断完整性。
   - 成功时运行 `scripts/cleanup_run.py --run-dir <本次临时目录> --artifact <最终文件> --mode transcript|review`。
   - 失败且无法生成最终产物时运行 `scripts/cleanup_run.py --run-dir <本次临时目录> --failed`，然后如实报告失败原因。
   - 清理范围只能是带本 Skill 标记的本次临时目录。不得删除原始录音、本地模型、最终产物、用户原有文件或以前运行留下的文件。
   - 清理后检查原录音目录：本次运行新增内容只能有当前模式的最终 Markdown；用户明确要求两个文件时除外。

## 完成前检查

确认以下条件全部满足后，才能宣布任务完成：

- Transcript 模式包含“转写说明”“转写正文”和至少一条带时间戳的内容；Review 模式每个正式问题都能关联到时间戳和候选人的真实回答；
- Review 模式中候选人的真实回答和推荐回答有清晰边界；
- 高置信度的文本修改可以在临时记录中核对；
- 听不清或存在歧义的语音仍有明确标记，没有被静默猜测；
- Review 模式的推荐答案没有加入缺乏依据的个人经历；
- Review 模式的问题、回答和追问保持原始时间顺序；Transcript 模式的所有语音片段保持原始时间顺序；
- 直接影响问答可信度的缺失、处理失败或音质问题已经简短披露；
- 最终产物没有暴露内部模型判断、处理性能或与用户目标无关的执行信息；
- 最终产物已经写入原录音目录并通过对应模式的结构化检查；本次临时运行目录已经删除。
- 本次运行没有在录音目录遗留 raw transcript、corrected transcript、分片音频、基准片段、缓存或分析草稿。

如果当前没有可用的转写方案，只完成只读检查，并准确说明缺少什么。不得假装已经分析录音。
