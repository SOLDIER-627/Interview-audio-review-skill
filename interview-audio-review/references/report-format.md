# 面试复盘报告格式

除非用户指定其他格式，否则使用下面的结构。报告语言默认与面试语言一致，也可以使用用户指定的语言。

## 输出文件

输入文件为 `interview.m4a` 时，最终只输出：

- `interview.review.md`：总体结论、面试问答、改进建议和推荐回答合并后的最终报告。

不得直接覆盖已有报告；同名文件存在时生成 `interview.review-YYYYMMDD-HHMM.md` 或递增版本。

原始转写 JSON、修复转写、音频分片、基准片段、纠错稿和分析草稿只放在本次临时目录。最终报告验证通过后清理该目录，不把这些文件保存到录音目录。

## 临时证据层

处理中，每个临时原始转写片段尽量包含以下字段：

```json
{
  "start": 125.4,
  "end": 131.8,
  "speaker": "说话人 A",
  "text": "语音识别模型的原始输出",
  "confidence": null,
  "source_chunk": "interview.part-001"
}
```

如果转写后端没有提供置信度，使用 `null`，不得自行编造分数。

临时证据层必须保留到最终报告完成并通过检查，便于核对问题、追问和回答。它不是最终交付物。

## 最终 review.md

### 1. 处理与证据说明

开头只需简短注明：

- 源文件和时长；
- 使用的转写后端，或已有转写稿的来源；
- 处理日期；
- 说话人角色映射；
- 直接影响问答完整性的音频缺失或听不清范围。

其余执行细节保留在内部临时记录中，不写入最终报告。

### 2. 总体结论

说明面试类型、有效问题数量和整体表现，控制在一段以内。

### 3. 面试问答与推荐回答

按时间顺序逐题列出，保留连续追问。统一使用下面的简洁结构：

```markdown
## Q1. <问题短标题> [00:02:05–00:03:01]

**面试官问题**

<经过纠错的完整问题>

**我的回答**

<只做高置信度纠错，不优化内容>

**改进建议**

<只写最有用的内容缺口、表达问题、风险表述和改进方式；使用分点>

**推荐回答**

1. <详细、忠于真实经历、适合口头表达的回答要点>
2. <继续补全关键依据、行动、结果或权衡>
3. <根据问题需要补充反思、边界或总结>

**补充（如有）**

<只列需要候选人如实补充的事实或值得准备的延伸信息；没有内容时省略本节>
```

重要追问使用 `Q1.1` 等子编号。问候、流程沟通和候选人反问可在单独小节概括。转写纠错和听不清内容继续在内部核对；最终报告直接使用纠正后的文本，并仅在对应问答处用 `[听不清]`、`[多人重叠]` 等标记，不另设专章。

## 完成与清理条件

- 最终文件名以 `.review.md` 或带版本号的 `.review-<版本>.md` 结尾；
- 文件位于原录音目录，不位于本次临时目录；
- 至少包含“处理与证据说明”“总体结论”“面试问答”“推荐回答”；
- 每个正式问题都有时间戳、真实回答、改进建议和详细的推荐回答；
- 推荐回答分点呈现，没有虚构个人经历；
- “补充（如有）”仅在确有内容时出现；
- 报告写入并验证后，使用 `cleanup_run.py` 删除本次临时目录；
- 清理后，本次运行在录音目录中只新增最终 review 文档。

## 证据规则

- 录音证据使用时间戳。
- 简历、岗位说明或笔记应标注为“用户提供的背景材料”。
- 外部事实必须给出引用，且不得改变候选人在录音中真正说过的内容。
- 推荐答案可以重新组织已知事实，但不得创造个人事实。
- 如果完整答案依赖缺失信息，必须使用醒目占位符，不能猜测。
- “只保留 review”不等于省略证据边界；真实回答与推荐回答必须明确区分，直接影响问答可信度的缺失信息应在对应位置标明。
