# 转写方案选择

输入包含音频或视频时阅读本文件。默认目标是零新增费用、录音留在本机，并在模型已经缓存后，让约一小时的双人面试尽量在二十分钟左右完成全部流程。

## 强制成本边界

- 默认禁止调用按量计费的语音识别、说话人分离或大模型 API。
- 用户允许云端处理不等于允许付费。只有服务当前明确免费、无需消耗付费额度，并且用户同意上传具体录音时，才可使用云端路线。
- 不得把试用金、限时免费额度或需要绑定付费方式的服务描述成“免费方案”。
- 云端免费资源不可用、排队过久或规则不明确时，立即回退本地方案，不要反复重试。

## 默认路线：Apple 芯片本地快速处理

| 阶段 | 默认选择 | 说明 |
|---|---|---|
| 音频检查 | `ffprobe` 或 macOS `afinfo` | 获取时长、声道、码率和格式，不修改原文件。 |
| 语音识别 | `mlx-whisper` + 本地 `models/whisper-large-v3-turbo` | 针对 Apple 芯片优化的多语言本地识别，适合中文夹英文的技术面试；本地目录不存在时才回退到 `mlx-community/whisper-large-v3-turbo` 仓库标识。 |
| 角色推断 | 根据带时间戳文本的问答结构推断 | 清晰双人面试的默认快速路径，不增加说话人模型耗时。 |
| 说话人分离 | 可选的本地 `pyannote.audio` `community-1` | 仅在角色推断不可靠时启用；需要免费 Hugging Face 账户、接受模型条款和访问令牌。 |
| 纠错与复盘 | 当前 Codex 任务 | 不额外调用转写 API；严格区分原稿、纠错、理解和推荐答案。 |

超过十五分钟的录音使用 `scripts/transcribe_chunked.py`，在隔离的临时目录生成、检查和合并分片；短录音可使用 `scripts/transcribe_local.py`。所有 JSON 都是本次运行的临时证据，不写入录音目录。依赖和模型的安装方式见 [本地安装与性能目标](local-setup.md)。

## 何时启用说话人分离

先使用快速路线。只有出现以下任一情况，并且已经影响问答归属时，才启用本地 `pyannote.audio`：

- 三人及以上参与对话；
- 面试官与候选人频繁插话或重叠；
- 候选人反问较多，单靠问号无法判断角色；
- 面试官有大量陈述，候选人也连续提问；
- 快速路线中超过 10% 的有效问答无法高置信度归属。

如果只是少数片段不确定，标记并人工复核这些片段通常比对完整一小时录音运行说话人分离更快。

## 五分钟基准测试

正式处理长录音前，从开头以外选取一段约五分钟、同时包含面试官和候选人的代表性片段：

1. 使用默认模型完成转写，记录墙钟时间。
2. 用 `处理秒数 ÷ 音频秒数` 计算语音识别实时系数。
3. 目标是语音识别实时系数不高于约 `0.15`，从而为角色推断、纠错和复盘保留时间。
4. 如果超过目标，依次尝试：关闭逐词时间戳、确认使用原生 arm64 Python、改用 `mlx-community/whisper-small-mlx`。
5. 如果样本术语错误明显，不要仅为提速换小模型；保留 Turbo 模型，并向用户说明总时间可能超过目标。

首次模型下载、依赖安装和网络等待不计入热运行性能。报告中同时写明样本结果、预计总耗时和实际总耗时。

## 长录音默认分片与幻觉处理

1. 保持原始文件不变。如果模型能直接读取源格式，不做转码。
2. 十五分钟以上默认按十分钟切片，相邻片段重叠十秒；保留绝对时间戳，按重叠区中点裁切去重。
3. 自动检查连续相同短语、单个短句覆盖异常长时段、文本内部循环等退化信号。
4. 可疑的十分钟片只改成五分钟小片重试一次。选择重复分数更低的结果；两次都异常则保留质量标记，交由报告标注为不可靠。
5. 不要因为局部异常重新识别整段录音，也不要无限改变提示词重试。
6. 从有效转写中整理专业词汇，按问题句式、回答长度和上下文恢复角色与问答。
7. 快速路线无法可靠区分角色时，再启用本地说话人分离并对齐时间戳。

这套策略来自真实运行：近五十分钟的录音整段识别在前半段退化为长时间重复短语，而十分钟独立分片恢复了有效内容。分片因此是长录音的默认可靠性措施，不只是失败后的补救。

## 音频预处理

- 不修改原始录音。
- 若立体声左右声道分别记录两人，优先直接分离声道，这是速度最快且最可靠的说话人区分方式。
- 不要默认激进降噪；过度降噪可能破坏辅音或技术名词。
- 只有格式不受支持、文件损坏或处理速度异常时，才用 `ffmpeg` 转成 16 kHz 单声道音频。
- 如需切分，按静音或自然轮次切分并保留少量重叠；合并时保留完整录音的绝对时间戳。

## 转写提示词汇

从简历、岗位说明、公司和产品名称、技术名词、缩写、指标、英文词以及用户词汇表中整理识别提示。提示词只能辅助识别，不能作为补写录音内容的依据。

## 不确定片段

建立不确定片段清单，记录时间戳、原始文本、可能候选词、角色候选和原因。只有录音或重复上下文充分支持时才能纠错；否则保留原文并标记 `[听不清]`、`[多人重叠]` 或 `角色不确定`。

Whisper 在静音、长思考或尾音中可能生成“感谢观看”、外语短句或单词循环。这类片段同时满足时间异常和重复特征时，按 `[静音/思考停顿，转写不可靠]` 处理，不作为候选人的真实回答、知识或态度证据。

## 临时文件与清理

- 所有分片音频、基准片段、原始 JSON、合并 JSON、纠错草稿和分析草稿必须位于本次临时目录。
- 最终报告必须先写到录音目录并验证完整，再清理临时目录。
- 清理只针对当前运行、带 `.interview-audio-review-run.json` 标记且名称以 `interview-audio-review-` 开头的目录。
- 不得为了满足“只保留 review”而删除用户以前已有的文件；该约束指本次运行不得新增其他持久化产物。

## 云端路线

云端只是可选替代路线，不是默认路线。执行前必须同时确认：

1. 用户明确同意上传该录音；
2. 服务当前确实不会产生费用；
3. 免费额度足够覆盖整段录音；
4. 隐私和保留政策可以接受；
5. 服务不可用时能够无成本回退本地。

任何一项不满足，就使用本地路线。
