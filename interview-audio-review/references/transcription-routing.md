# 转写方案选择

输入包含音频或视频时阅读本文件。默认目标是零新增费用、录音留在本机，并在模型已经缓存后，让约一小时的清晰双人面试尽量在二十分钟左右完成全部流程。

## 强制成本边界

- 默认禁止调用按量计费的语音识别、说话人分离或大模型 API。
- 用户允许云端处理不等于允许付费；服务免费状态、额度、隐私与支付要求必须单独确认。
- 不得把试用金、限时免费额度或需要绑定付费方式的服务描述成稳定免费方案。
- 云端免费资源不可用或规则不明确时，回退本地方案。

## 本地平台路由

| 平台 | 音频检查与解码 | 语音识别 | 默认模型 |
|---|---|---|---|
| Apple 芯片 macOS | `ffprobe` / `ffmpeg` | `scripts/transcribe_local.py` 或 `transcribe_chunked.py` | MLX `whisper-large-v3-turbo` |
| Intel macOS | PyAV，可选 `ffmpeg` | `scripts/transcribe_faster_whisper.py` | CPU `small` + INT8 |
| Windows CPU | PyAV，可选 `ffmpeg` | `scripts/transcribe_faster_whisper.py` | `small` + INT8 |
| Windows NVIDIA GPU | PyAV，可选 `ffmpeg` | `scripts/transcribe_faster_whisper.py` | `turbo` + FP16 |

所有路线都输出统一的带时间戳 JSON，后续角色推断、转写纠错、问答还原和报告结构保持一致。依赖和命令见 [本地安装与性能目标](local-setup.md)。

## Apple 芯片长录音

超过十五分钟默认使用 `scripts/transcribe_chunked.py`：

1. 十分钟分片，相邻片段重叠十秒；
2. 合并为完整录音的绝对时间轴；
3. 检查连续相同短语、长时间短句和文本内部循环；
4. 可疑十分钟片改成五分钟小片重试一次；
5. 两次都异常时保留质量标记，不根据上下文补写。

长录音分片是可靠性策略，不只是失败补救。不要因为局部异常反复重转整段录音。

## Windows 与 Intel Mac 长录音

使用 `scripts/transcribe_faster_whisper.py` 对源文件直接转写，并默认启用 Silero VAD，过滤长静音和降低幻觉风险。脚本未指定 `--output` 时自动创建带清理标记的系统临时运行目录。

完成后仍需检查：

- 连续重复短语；
- 单个短句覆盖异常长时段；
- 静音处生成“感谢观看”等无关文本；
- 文本内部循环；
- 长时间无任何分段。

发现局部异常时，只复核对应时间范围。若当前平台具备 FFmpeg，可截取该范围后用同一后端重试一次；仍异常则在报告中标记不可靠范围，不得无限重试。

## 角色推断与说话人分离

默认根据时间戳、问题句式、回答长度、上下文和轮次推断面试官与候选人。只有以下情况已经影响问答归属时，才启用本地 `pyannote.audio`：

- 三人及以上参与；
- 双方频繁插话或重叠；
- 候选人反问较多，单靠语义无法判断；
- 超过约 10% 的有效问答无法高置信度归属。

少量片段不确定时，标记并复核局部通常更快。

## 五分钟基准与降级顺序

正式处理长录音前选取一段代表性五分钟片段：

1. 使用平台默认模型转写并记录墙钟时间；
2. 计算 `处理秒数 ÷ 音频秒数`；
3. 实时系数尽量不高于 `0.15`；
4. 太慢时先关闭逐词时间戳，再确认后端与硬件路由；
5. 仍然太慢才使用较小模型，并在报告中披露准确率取舍。

如果样本中的技术术语错误明显，不要只为达标而无说明地降低模型。二十分钟是优化目标，不是承诺。

## 音频预处理

- 不修改原始录音；
- 左右声道分别记录两人时，优先分离声道；
- 不默认激进降噪，避免破坏辅音和技术词；
- 只有格式不支持、文件损坏或速度异常时才转为 16 kHz 单声道；
- 分片或局部重试必须保留绝对时间戳并处理重叠去重。

## 转写提示词

从用户材料中整理姓名、公司、岗位、产品、技术名词、缩写、指标和英文词，作为 `--initial-prompt`。提示词只能辅助识别，不能作为补写录音内容的依据。

## 不确定片段

记录时间戳、原始文本、候选词、角色候选和原因。只有证据充分时才能纠错；否则使用 `[听不清]`、`[多人重叠]`、`可能是：...` 或 `角色不确定`。

静音、思考或尾音中出现重复短语、无关结束语或外语碎片时，标记为 `[静音/思考停顿，转写不可靠]`，不作为候选人的知识或态度证据。

## 临时文件与清理

- 分片、基准音频、原始 JSON、纠错稿和分析稿全部放在本次系统临时目录；
- 最终报告写到录音目录并验证完整后，再运行 `cleanup_run.py`；
- 清理仅针对名称以 `interview-audio-review-` 开头且包含合法标记的当前运行目录；
- “只保留 review”表示本次运行不新增其他持久化文件，不得删除用户原有文件。

## 云端路线

云端不是默认路线。执行前必须同时确认：用户同意上传具体录音、当前服务确实免费、额度足够、隐私与保留政策可接受、失败时可无成本回退。任何一项不满足，就使用本地路线。
